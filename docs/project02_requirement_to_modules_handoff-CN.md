## 1. 功能目标

使用者用自然语言描述设备或工艺需求，系统完成以下处理：

```text
需求描述
  → 识别工艺能力
  → 补齐能力依赖
  → 推荐所需模组并解释原因
  → 使用者确认模组
  → 生成相应布局方案
  → 展示、Replay及CAD验证
```

短期目标是先在项目02走通可靠、可解释、可测试的 Demo；中期目标是支持任意确认模组子集；长期目标是复用统一能力模型支持项目01、03、05、06。

## 4. 当前明确的限制

1. **只支持项目02**：项目编号和知识库仍为项目专用。
2. **解析能力有限**：当前是词典和确定性规则，不处理复杂语义、模糊描述及大范围同义词。
3. **求解器固定八模组**：非完整八模组集合可以完成推荐和确认，但不能进入当前布局求解器。
4. **不能自动追问**：缺少节拍、产品数量或是否需要扫码等信息时，只列出缺失信息，尚未形成多轮澄清。
5. **未处理规则冲突**：例如同时出现“需要CCD”和“不需要CCD”时，尚缺少独立冲突报告和人工裁决流程。
6. **功能完整不等于工程可制造**：推荐结果不包含品牌、型号、节拍、精度、冗余和采购选型判断。
7. **布局展示不等于CAD验收**：现有结果仍为 `productionReady=false`，需要 Replay、条件 B-Rep、运动扫掠和维护空间检查。

## 5. 后续完善规划

### 阶段二：动态模组子集求解（最高优先级）

目标：让确认后的模组集合真正决定参与求解的组件，而不是只能使用固定八模组。

建议实现：

1. 根据确认 JSON 动态生成项目配置；
2. 只为已选模组创建求解变量；
3. 按已选能力加载相应工艺约束；
4. 自动删除引用未选模组的约束，或报告依赖缺失；
5. 动态生成碰撞检查组合和条件 B-Rep 路由；
6. 展示页只渲染已选模组；
7. 增加三类用例：基础点胶、点胶＋扫码、完整八模组。

验收标准：

- 三类模组集合均能独立完成推荐、确认、求解和展示；
- 求解输入组件集合与确认集合完全一致；
- 不存在引用缺失模组的悬空约束；
- 相同输入可稳定得到可复现结果。

### 阶段三：规则配置化与澄清问题

目标：降低新增项目和修改规则时的代码成本。

建议实现：

1. 将能力、关键词、依赖和能力—模组映射迁移到版本化 JSON/YAML；
2. 增加配置 Schema、版本号和启动时校验；
3. 为节拍、数量、扫码、CCD、称重等关键信息定义澄清问题；
4. 为矛盾需求增加冲突报告，不静默选择其中一方；
5. 建立需求语句回归数据集。

验收标准：

- 修改能力映射不需要修改 Python 业务逻辑；
- 配置存在循环依赖、未知模组或重复能力时能够拒绝启动或明确报警；
- 信息不足时能够返回结构化澄清问题；
- 回归语句的推荐结果保持稳定。

### 阶段四：多项目复用

目标：在统一能力本体下接入项目01、03、05、06。

建议实现：

1. 复用共同能力定义；
2. 每个项目只配置自己的模组实现、组合模组和布局约束；
3. 支持一个模组承载多项能力，例如项目02 A700 的清洁＋称重；
4. 支持同一能力在不同项目中由不同模组实现；
5. 对五个项目分别建立原型对比和合理性观察用例。

验收标准：

- 不复制项目02整套推荐代码；
- 五个项目均能从需求生成可解释的模组集合；
- 项目差异能够追溯到配置项；
- 至少每个项目完成一个布局展示用例。

### 阶段五：CAD闭环与工程验收

目标：把“功能推荐和布局可行”提升为“实体装配可验证”。

建议实现：

1. 将确认方案 Replay 到新的 SolidWorks 装配体；
2. 普通模组对使用膨胀包围盒严格分离；
3. 门洞、框架和嵌套组合使用条件 B-Rep 精检；
4. 增加方向、运动扫掠、软管/拖链、维护抽出和最小间隙检查；
5. 保存装配体、检查结果、截图和机器状态 JSON。

验收标准：

- Replay 组件数量及位姿与求解结果一致；
- 所有规定的静态碰撞门禁通过；
- 保存重开后结果可复测；
- 只有完成规定工程检查后才能将 `productionReady` 设为 true。

## 6. 建议的下一次开发任务

下一次建议直接实施“阶段二：动态模组子集求解”的最小切片：

1. 选定三个固定测试需求；
2. 从确认结果生成动态组件白名单；
3. 让求解器和展示层只处理白名单内模组；
4. 对缺失依赖执行硬失败；
5. 完成三类用例的接口、展示和回归测试。

这样做的原因是：当前需求推荐已经可以正确告诉使用者“需要哪些模组”，但如果确认结果不能改变实际参与求解的模组，业务链路仍存在断点。动态子集求解是从 Demo 展示走向真正需求驱动方案生成的关键一步。

## 9. 2026-08-28：结构基准与求解顺序调整

- A600应作为“结构基准/站体边界”进入布局推理，但不与八个工艺模组混为同一种能力模组。
- 项目02完整Mate图确认A600是机械安装关系中心；需求推荐结果进入布局阶段时，必须自动补入A600上下文。
- 布局顺序规划调整为A600→A800→A180→功能模组侧别→A100覆盖反求；当前固定八模组求解器尚未实现这一动态依赖顺序。
- “需要扫码”仍推荐A180，但其可行性必须由A800条码点、扫描工作距离、视场和无遮挡约束验证，不能只检查模块是否存在。
- 详细机械证据和语义缺口见 `docs/project02_module_mate_graph-CN.md`。
