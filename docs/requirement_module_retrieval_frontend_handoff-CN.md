# 自然语言模组检索与前端展示——开发交接文档

> 交接日期：2026-09-10
> 接手角色：自然语言需求匹配、模组/文件检索、前端界面开发
> 明确不负责：动态子集求解、空间布局算法、SolidWorks Replay、配合重建和干涉检查。

## 1. 任务目标

使用者输入一段自然语言需求，系统识别需要的工艺能力，检索相应项目中的模组和CAD文件，并在网页上清晰展示结果、依据及不确定项。

目标流程：

```text
用户输入自然语言需求
  → 提取显式能力、否定项和简单数量
  → 按确定性规则补齐必要能力依赖
  → 在指定项目或全部项目中检索对应模组
  → 返回模组编号、功能、CAD文件、置信度和推荐理由
  → 前端筛选、查看、复制路径或提交人工确认
```

本任务的终点是“找到并展示正确的模组/文件”。确认结果是否参与布局求解，不属于本次交接范围。

## 5. 建议的数据模型

建议新增版本化注册表，例如：

```json
{
  "schemaVersion": "module-retrieval-registry/v1",
  "projects": [
    {
      "projectId": "02",
      "sourceAssemblyPath": "...SLDASM",
      "modules": [
        {
          "moduleCode": "A180",
          "label": "条码扫描模组",
          "capabilities": ["barcode_traceability"],
          "cadId": "FL9A24D062A180.001",
          "filePath": "...\\FL9A24D062A180.001.SLDASM",
          "referencedConfiguration": "Default",
          "fileExists": true,
          "confidence": "confirmed",
          "evidence": ["PPT", "prototype-CAD"]
        }
      ]
    }
  ]
}
```

建议把以下概念分开：

- `capability`：用户需要的工艺能力；
- `module`：承担一种或多种能力的工程模组；
- `cadId`：图纸/装配编号；
- `filePath`：实际可读取的文件；
- `componentName`：某个原型装配体中的实例名；
- `confidence/evidence`：识别结论的可信度和来源。

不要把`componentName`当成文件路径，也不要通过未经限制的全盘模糊搜索直接把任意文件返回给前端。

## 6. 建议的接口调整

建议保留现有接口兼容性，并增加通用接口：

```text
POST /api/demo/module-retrieval/recommend
```

请求建议：

```json
{
  "requirement": "需要点胶、扫码和CCD定位",
  "projectIds": ["02"],
  "includeOptional": true
}
```

响应至少包含：

- 规范化需求；
- 显式能力、依赖能力和排除能力；
- 每个能力的触发证据；
- 模组编号、名称、项目、能力、必选/可选状态；
- 完整CAD文件路径和存在状态；
- 置信度、数据来源和警告；
- 未识别文本、缺失信息和冲突项；
- 注册表版本及结果生成时间。

接口应只返回注册表中允许的路径；收到未知项目、空需求或损坏配置时应返回明确的4xx错误。

## 7. 前端建议

### 7.1 页面结构

```text
项目范围选择
自然语言需求输入
解析/检索按钮
────────────────
识别到的能力与依赖
冲突、缺失信息和未识别内容
────────────────
推荐模组卡片
  ├─ 模组编号/名称
  ├─ 项目及功能标签
  ├─ 必选/可选和推荐理由
  ├─ CAD编号、完整路径和文件状态
  └─ 置信度及证据来源
────────────────
筛选、复制路径、导出结果/人工确认
```

### 7.2 组件拆分建议

- `RequirementInput`：项目范围、需求文本、提交状态；
- `CapabilitySummary`：显式能力、依赖、否定和冲突；
- `ModuleResultList`：模组结果容器；
- `ModuleResultCard`：编号、功能、理由、置信度；
- `CadFileResult`：文件路径、存在性和复制操作；
- `RetrievalWarnings`：缺失信息、待确认项和错误。

### 7.3 交互原则

- 必选与可选必须视觉区分；
- “未找到文件”和“没有这个能力”必须区分；
- 推断结果不能显示成已确认；
- 请求失败时保留用户输入和上一结果；
- 搜索进行中禁止重复提交；
- 长路径需要换行、复制和完整提示；
- 不在前端自行拼接Windows路径，以后端注册表为准。

2. 输出未识别片段和结构化澄清问题；

4. 再评估是否使用大模型做候选能力提取。即使引入大模型，最终结果仍必须经过确定性能力、依赖和文件注册表校验。

## 11. 开发注意事项

- 工作区存在其他长期分支功能，修改前先检查`git status`，不要覆盖无关改动；
- 本任务不需要启动SolidWorks，避免引入COM和大型装配体加载时间；
- 数据配置必须有Schema、版本和启动/加载校验；
- 新生成索引使用新文件，避免覆盖人工确认数据；
- 文件路径属于Windows本地路径，前端只展示/复制，不能假设浏览器可直接打开；
- 项目05、06供胶模组仍有待确认项，必须如实展示；
- 组合模组可能覆盖多个能力，例如项目02 A700同时覆盖清洁和称重；
- 同一能力在不同项目可能由不同编号实现，不能把项目02编号推广到其他项目。
