# 项目02：A600锚定装配顺序门禁

## 1. 本次功能修改的意义

机械工程师确认的装配原则不是“先固定龙门，再把其他模组塞进行程范围”，而是：

```text
A600箱体/操作面
  → 按厂商XYZ接口固定A800传输
  → 依据条码侧、工作距离和视线固定A180扫描
  → 按操作侧剩余空间选择A500/A700/A300所在侧
  → 最后定位A100，使双阀行程覆盖工作位和全部服务点
```

本次新增“顺序求解就绪度门禁”，把上述工程知识转成可机读的五阶段计划。它不改变当前八模组粗排结果，而是明确防止该结果被误称为已经符合A600锚定装配原则的正式解。

## 2. 实现内容

新增 `apps/demo-backend/src/demo_backend/assembly_sequence.py`：

- 读取项目02真实模组级配合图；
- 将A600–A800、A600–A180、A600–A500/A700/A300、A600–A100配合束作为机械安装证据；
- 检查A600是否进入求解几何、操作面是否确认；
- 区分A600–A800原型世界坐标平移差和厂商确认XYZ参数；世界平移差不得直接解释为A600局部接口尺寸；
- 检查扫描原点、条码点、工作距离、条码侧和视线约束；
- 检查操作侧空间是否足够，并给出功能模组侧别；
- 检查双阀行程区、传输工作位和功能服务点是否已定义且实测；
- 输出每阶段 `ready / provisional / blocked`、证据来源及缺失输入。

## 6. A600–A800配合面接口分析

真实配合束只有`重合35＋宽度9`。`重合35`把A800安装接触面约束到A600支承面，确定Z并限制两个转角；`宽度9`把A800居中在A600两张宽度定位面之间，确定Y和剩余姿态。两者共同锁定Y、Z及姿态，但没有端面重合、距离或销孔配合来锁定沿传输长轴的X。

以当前配合特征构造的粗定位基准为`(376.3, 0, 0) mm`：Y=0、Z=0由配合直接决定；X=376.3 mm来自原型中`宽度9`的A800两张特征面中点投影，只是原型测量值，不是配合约束值，更不是厂商参数。

修改意义：把原先笼统的“缺少厂商XYZ”缩小为一个明确的剩余自由度——只需补齐长轴X基准；同时避免把组件原点或包围盒中心误作安装接口。

## 8. A180扫描出光面与A800条码面的稳定采集框架

第三阶段已从一个笼统的“扫描点未实测”拆成四个独立门禁：

1. A180内真实`SR-X100`扫描器的出光面已记录；
2. A800载具/产品的条码面已记录；
3. SR-X100工作距离或允许范围已由规格/工艺确认；
4. 所选出光面法向已确认代表实际光轴方向。

新增 `scripts/capture_project02_optical_point.py`。工程师在SolidWorks中选择面后，工具记录顶层模组、叶零件路径、持久面映射、面中心/法向、面积等几何指纹，并把世界坐标转换成所属模组底面中心坐标系内的局部`(u,v,height)`。因此求解器移动A180或A800时，工艺点会随所属模组刚体移动，不依赖原型绝对世界坐标。

安全门禁如下：

- 扫描面必须位于A180子树，默认还必须属于已识别的`248004电气-sr-x100-0801A.SLDPRT`叶零件；
- 条码面必须位于A800子树；
- 两个面都捕获完成后才允许写回请求；
- 写回点位不会自动确认工作距离或光轴方向，避免用CAD面几何代替工程判断；
- 当前证据文件为 `demo/layout_previews/project02_scanner_barcode_points.json`：A180光轴中心为对称特征CAD推断，A800条码为`模拟二维码.SLDPRT`直接面测量；两点均已进入请求，但工作距离规格和动态扫描位仍保持未确认。

测试结果：后端完整回归`90/90`，前端生产构建通过，真实HTTP求解可生成3个候选，装配顺序校验`16/16`；当前第三阶段仍正确保持`blocked`。

实际采集顺序：先在原型中选择A180内SR-X100的出光平面并运行`--target scanner`，再选择A800实际条码所在平面并运行`--target barcode --apply`。若条码只是标签纹理而没有独立CAD面，应由工程师选择承载条码的安装面，并另行确认条码中心偏移，不能直接采用整面中心作为最终点。
