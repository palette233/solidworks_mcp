# 项目02：v42依赖消融实验

## 1. 目的

回答两个问题：

1. 当前v22是否只是以另一种形式复刻历史v42结果；
2. 移除v42成对碰撞反馈后，仅凭CAD几何、工艺点和通用约束，能否快速得到不同且合理的解。

本实验只运行离线求解与2.5D几何审计，不启动SolidWorks、不执行Replay或B-rep。只有出现“硬可行且相对v22有实质变化”的候选，才允许进入CAD验证。

## 2. 固定基线与三组实验

- 冻结基线：v22选案、增量B-rep闭环、九模组SLDASM及v42占用体均记录SHA-256，见`demo/layout_previews/project02_v22_frozen_baseline_manifest.json`。
- A组：当前v42历史反馈模型；用于确认现有结果可重复。
- B组：移除v42，以CAD叶体捕获生成无伙伴历史的几何占用体；保留工艺约束和局部接口约束。
- C组：在B组基础上，移除A300/A500/A700非必要位置窗口和候选偏置；保留A180–A200、A200–A800局部接口。

几何占用体采用分层表示：A100/A200门洞结构及A300/A500/A700服务模组使用叶实例联合盒，避免把真实开口填实；A180/A800/T401使用一级子树联合盒控制计算量。当前共574个盒，不含`collisionPartnerCodes`和历史干涉对。

## 3. 实现入口

- 消融请求、几何占用体、位姿比较和已知位姿复核：`apps/demo-backend/src/demo_backend/project02_ablation.py`
- 可传入内存请求且不覆盖当前展示选案：`apps/demo-backend/src/demo_backend/layout_preview.py`
- 实验命令：`python scripts/run_project02_dependency_ablation.py`
- 仅刷新哈希、几何与已知位姿审计：`python scripts/run_project02_dependency_ablation.py --reuse-experiments`
- 单元测试：`apps/demo-backend/tests/test_project02_ablation.py`

## 4. 2026-09-05实验结果

| 组别 | 结果 | 时间 | 解释 |
|---|---:|---:|---|
| A | 3个硬可行解 | 3.33 s | rank 1与v22位姿完全一致，证明当前算法确定性可重复 |
| B | 90 s门限后超时 | 103.78 s实际返回 | 停在A700候选验证；A180已接受4个、A200已接受9个、A700尚未接受候选 |
| C | 90 s门限后超时 | 90.02 s | 同样停在A700；移除服务位姿偏置仍未越过维护空间/传输静态区门禁 |

B/C是“不确定”，不是“已证明无解”。本轮没有产生可推荐给CAD的不同候选，因此没有执行Replay或B-rep。

## 5. 关键对照发现

将已知可接受的v22 rank 1位姿直接放入B组完整几何规则，得到7项硬失败：

- 6项为估算维护/服务空间与A100、A200、A700或A800几何占用相交；
- 1项为A300–A800叶包围盒命中，该对象对在当前策略中仍需条件B-rep解释。

这说明v42不是简单“保存v22位姿”，但它是**稀疏、伙伴限定的历史碰撞知识**。把它直接替换为“所有叶几何命中均为硬失败”，同时改变了碰撞语义；现有100 mm维护带又是原型/PPT估计且`confirmed=false`。因此当前B/C失败同时包含两件事：搜索成本上升，以及新旧几何模型不等价。

## 6. 当前结论与边界

- 可以确认：v22并非读取原型顶层位姿后直接复制；A组的完全重复来自确定性候选、约束和评分。
- 也必须承认：v22仍强依赖项目02的v42伙伴碰撞反馈、安装基准、服务点、光学和行程估计，尚不能称为通用约束独立生成。
- 不能据B/C超时声称“去掉v42一定无解”；也不能把完整叶AABB命中直接当作实体干涉。
- 不能进入CAD验证，因为没有出现新的硬可行候选；此时做B-rep只会验证一个尚未闭合的建模假设。

## 7. 后续规划

1. 为约束增加证据等级：实体禁入、安装基准、光学/可达等确认证据作为硬约束；未确认维护带先作为软评分或人工警告。
2. 非凸框架、门洞和嵌套对象对继续采用“叶AABB宽相命中→条件B-rep”，不把AABB命中直接升级成实体碰撞。
3. 增加“已接受位姿兼容门禁”：替换占用模型后，必须先解释v22为何新增失败；若是约束规格有意收紧，应明确标记，而不是悄然称为等价消融。
4. 完成上述语义拆分后重新运行B/C；只有得到不同的硬可行Top-3，才进入展示目测、唯一选案、Replay及增量B-rep。

修改意义：把“是否复刻v42”从口头判断升级为可重复的版本化实验，并发现真正阻塞完全去历史依赖的不是单一参数，而是维护空间置信度、非凸几何宽相语义和搜索性能三者尚未分层。

当前状态分为三层：

- 可交付基线：A组/v22可确定性复现，九模组直接装配体已经完成保存重开和策略级干涉闭环；

3. 在求解前运行v22兼容门禁，输出每项新增失败的证据来源与处理级别；
4. 为A700候选验证增加候选数、拒绝原因和分阶段耗时，重新运行B/C并保留固定时间预算；

阶段成功判据：至少一个候选不读取v42伙伴碰撞标记；全部已确认硬约束通过；未确认维护空间只产生显式风险提示；所有非凸AABB命中均被列入可执行的条件B-rep计划；结果、时间和依赖清单可由JSON复核。

功能修改意义：本次只恢复和冻结开发决策，没有宣称产生新解。它将下一次代码迭代限定在离线约束语义与搜索诊断层，避免再次用长时间SolidWorks运行掩盖约束模型本身的不一致。
