# 项目02语义端口与增量装配 Demo

更新日期：2026-09-15

## 1. 目标

验证以下最小闭环：在现有装配图中增加一个子装配体节点，通过具有工程语义的端口选择实际面端点，生成配合图 Patch，并把增量后的有效图重建为独立 SolidWorks 装配体。

本阶段不直接修改项目02原型，也不宣称仅靠一条配合即可完全确定新增组件的六自由度。

## 2. 数据链路

```text
工程连接意图
  → 语义端口目录（端口属于哪个模组、接口类型、证据、状态）
  → 面端点目录（EndpointId、叶零件、Body/Face索引、局部几何）
  → 兼容模板（端口角色如何编译成基础配合）
  → mate-graph-patch/v1（新增组件节点 + 新增配合边）
  → Effective Mate Graph
  → SolidWorks 独立重建、另存、重开复核
```

职责边界：

- 面端点目录负责“稳定恢复哪个几何实体”。
- 语义端口目录负责“该实体在工程上能做什么”。
- 兼容模板负责“两个端口如何转换为一组配合或布局约束”。
- 配合图 Patch 负责记录可编辑的节点/边增量。
- SolidWorks 执行器负责把有效图物化为新装配体。

## 3. 已实现功能

### 3.1 配合图支持新增组件节点

`compile_mate_graph_patch`新增`addModule`/`addComponent`操作，校验`ModuleToken`、`HierarchyPath`和源文件路径，拒绝重复层级路径，并在审计信息中保留新增节点来源。

功能意义：配合图不再只能修改已有边，而可以表达“向已有装配体加入新子装配体”这一核心增量操作。

### 3.2 语义端口目录、兼容校验与编译器

新增`semantic-port-catalog/v1`：

- 端口具有稳定`portId`、所属模组、类别、接口类型、确认状态和证据；
- 一个端口可按角色绑定一个或多个`EndpointId`；
- 连接模板描述端口类型兼容性、端点角色和需要生成的基础配合；
- 连接请求可同时携带待新增组件和参数覆盖；
- 编译结果包含Patch、有效图、语义来源审计和自由度效果说明。

功能意义：上层需求不再直接猜测Face索引，而是先选择工程语义端口，再由端口绑定到已验证的面端点。

### 3.3 项目02确定性样例

3. 当前执行器生成独立新装配体，不是在任意已打开装配体中原位插入组件。
4. 当前目录只有A500/A700两个演示端口，尚未覆盖A600安装面、孔轴、定位销或其他模组。
5. 尚未在本轮运行真实SolidWorks增量装配；当前关系仍有剩余自由度，因此只完成离线图闭环、真实API联调和展示层视觉验收。
6. 配合重建成功不等于实体无干涉；后续仍需AABB宽相和条件B-rep复核。

## 6. 后续规划

### 优先级1：建立可完全定位的机械端口组

为A500/A700补充至少两类相互独立的接口参考，例如安装平面、定位轴/孔、方向平面或点。用自由度分析验证模板生成的配合组合是否达到预期约束状态，并防止冗余或过约束。

原因：没有足够独立的几何参考，任何“自动加入组件”都只能恢复局部关系，无法稳定确定最终位姿。

### 优先级2：执行真实SolidWorks独立重建

从展示层提交已预检请求，生成新SLDASM，保存后关闭重开，核对组件数、配合数、参数、错误码、刚柔性和约束状态。

原因：图级正确只能证明数据表达和编译正确，仍需验证SolidWorks API对真实装配语义的执行结果。

### 优先级3：加入实体安全门禁

先对普通实体模组做膨胀AABB严格分离；对门洞、框架、允许嵌套关系仅路由选择性叶级B-rep；存在未接受干涉时拒绝发布。

原因：配合合法不代表实体不碰撞，且分级检查可以避免对所有模组对执行昂贵B-rep。

### 优先级4：扩展为通用“新增模组”工作流

增加端口搜索与排序、端口兼容矩阵、自然语言意图结构化、人工确认、图级自由度诊断，以及对现有装配体副本的原位增量执行。

原因：先把项目02的确定性样例做严，再扩展到跨项目和自然语言，能避免把识别误差、几何恢复误差和CAD执行误差混在一起。

## 7. 第二阶段：A500完整语义安装闭环（2026-09-15）

本节取代第3.3、4、5节中“仅有距离8、未运行SolidWorks”的第一阶段状态说明。

### 7.1 原型关系复核与模型修正

从项目02完整模组配合图确认，A500的主要安装定位不是来自A700，而是来自A600：

### 7.2 新增能力

功能修改意义：增量装配不再重复求解已经装好的复杂基座；同时完整保留工艺语义，又不因冗余尺寸制造过约束。

### 9.2 真实三模组检查结果

检查对象：`A500 + A600 + A700`语义增量装配体。

| 模组对 | 顶层AABB | 叶级B-rep结果 | 耗时 |
|---|---|---:|---:|
| A500–A700 | 重叠，需精检 | 11组实体干涉 | 95.62 s |
| A500–A600 | 重叠，需精检 | 0组实体干涉 | 173.52 s |
| A600–A700 | 重叠，需精检 | 8组实体干涉 | 419.25 s |

总计：顶层3模组、3个模组对，0对可由顶层AABB直接证明分离，3对进入精检；2对存在实体干涉。精检计算失败为0，因此结果不是几何内核异常。

进一步以“源零件文件名＋叶实例名”的稳定身份对历史原型证据做多重集比较：

- A500–A700：当前11组与独立干净容器v42的11组完全一致；项目02原型上下文基线为0，因此11组全部是独立重建新增干涉；
- A600–A700：原型基线已有4组，当前8组中4组与基线一致，另有4组新增；
- 这与既有v42/v43实验结论相互验证：相同顶层刚体位姿下，重新插入A700后其内部柔性/配置姿态可能漂移；在原型上下文内执行则A500–A700为0。

因此，本轮问题不能用“调整50 mm距离”解决；应保留A500端口与配合结果，优先修复既有柔性上下文的内部状态继承。

性能结果：

此前A100顶层配合虽然完全约束，但其内部A150仍为柔性，保存重开后会落入另一合法槽位状态，导致`FL408AF-00020`与A600上盖产生原型中不存在的接触。排查确认：

- A150的`Slot2`在独立装配体中可在0%与100%之间移动约100 mm；
- A100在整机中的世界X轴方向与局部X轴相反，直接采用100%会把阀头移向错误方向；
- 仅固定A150或仅固定顶层A100均不足以阻止父级重新求解内部状态。

最终采用“双层刚性工作快照”：A150固定在`Slot2=0%`，A150在A100内设为刚性，A100在顶层也设为刚性。保存、关闭、重新打开后：

- `FL408AF-00020`世界坐标恢复为`(-0.8292709617, 1.1197975478, -0.4935771212) m`；
- `A121003`世界坐标恢复为`(0.0440214636, 1.0155292352, -0.4935771212) m`；
- 两者均与原型目标一致；
- A100/A600不再出现新增干涉，剩余3组稳定叶件接触均属于原型基线。

最终装配体：

`demo/semantic_ports/project02_ordered_true_increment_v1/step06_A600_A800_A180_A700_A300_A500_A100_V6_DUAL_RIGID.SLDASM`

同时新增`list_top_level_component_subtree_poses`，只遍历指定顶层模组子树。A150子树查询约`2.21 s`，避免每次为检查两个关键叶件而遍历完整整机；相关.NET测试52项通过。

功能修改意义：静态Demo现在能稳定重现指定工作状态，而不是依赖SolidWorks在柔性自由度中选择一个可解状态；但该结果只证明一个静态工作快照，不替代全行程运动学验证。

### 17.2 A600/A800复杂安装对闭环

A600/A800属于框架/嵌套安装关系，不能要求包围盒或B-rep结果绝对为零。候选与原型各自的全量叶级检查均得到104个原始接触和同一个布尔内核错误547。采用“来源文件路径＋末端实例名”作为稳定身份后：

- 原型和候选均为52个唯一叶件接触签名；
- 候选新增签名为0，缺失签名为0；
- 唯一失败对象在两边均为`FL209AK-00001-1 ↔ 056-19475LJ240420-A1-001-A_56-1`；
- 对该失败对象改用SolidWorks官方`ToolsCheckInterference2`复核，原型和候选均明确返回无干涉。

门禁策略升级为`noNewInterferenceOverAcceptedBaselineWithOfficialFallback`：已完成实体对必须无新增接触；低层布尔失败必须由官方选择器覆盖同一对象并返回无干涉。兜底对象不一致、数量不一致或仍有干涉时均拒绝。

性能记录：原型首次全量基准约`1466.26 s`，原型失败对兜底约`311.83 s`，候选失败对兜底约`238.67 s`。因此该结果被版本化缓存；只有源几何或A600/A800相对安装位姿变化时才重建，日常求解不重复做24分钟全量检查。

功能修改意义：既没有把原型安装接触误判为碰撞，也没有把内核失败伪装成“精确通过”；通过一次性基准、稳定身份和针对性官方复核，把复杂安装对纳入可审计发布门禁。
