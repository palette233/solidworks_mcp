# 自然语言驱动的可解释 CAD 装配流程

> 目标：把“先安装传输模组，再安装扫描模组……”这类自然语言要求，转换为可审计、可逐步执行、可暂停恢复，并由真实 SolidWorks 文件和碰撞证据支撑的完整装配流程。
>
> 本文是该主线的统一进展记录。每个阶段均记录功能意义、闭环测试、问题与阻塞点。

## 1. 总体流程

```text
自然语言要求
  → 受控意图解析
  → 版本化项目配置
  → 通用装配意图/计划
  → 顺序与依赖硬门禁
  → 逐步 SolidWorks 执行
  → 保存、重开与位姿复核
  → AABB 快检/条件 B-rep 精检
  → 证据清单与时间审计
  → 静态 Demo 或生产动态放行
```

当前项目02的已验证顺序为：

`A600 → A800 → A180 → A700 → A300 → A500 → A100 → A200 → T401`

其中 T401 对应两个 CAD 实例，因此最终是 **9个语义阶段、10个顶层 CAD 对象、45个顶层对象对**。

## 3. 阶段1：版本化项目配置

### 修改内容

- 新增 `project-assembly-profile/v1` 数据格式；
- 将项目02的模组名称、别名、顺序依赖、实例数量、执行策略、碰撞策略和闭包证据路径集中到一个 JSON；
- 每个关键参数标记来源置信度：厂商确认、工程师确认、CAD测量、原型推断或临时估计；
- 配置加载时校验重复别名、未知依赖、非法来源等级，并生成稳定 SHA-256 摘要。

### 功能意义

自然语言解析器和 CAD 执行器不再分别维护互相漂移的硬编码规则；每次执行都能说明“使用的是哪一版项目参数”。

### 闭环测试

- 配置完整性、摘要稳定性、别名冲突、未知依赖等测试：**18/18 通过**。

### 问题与阻塞点

- 旧代码中的常量暂时保留为历史可读内容，运行时已由配置覆盖；后续可删除重复定义。
- 多个参数仍属于“从原型推断”，可以用于项目02粗布局和 Demo，不等于厂商生产参数。

## 4. 阶段2：通用装配意图和计划契约

### 修改内容

- 新增 `assembly-intent/v1`：记录原始自然语言、解析得到的模组顺序、项目配置版本和意图摘要；
- 新增 `assembly-plan/v1`：记录每一步的前置依赖、安装原则、验收项、执行边界和计划摘要；
- 同一输入、同一配置生成相同摘要；顺序发生改变时摘要同步变化。

### 功能意义

把自然语言、项目规则和 CAD 执行解耦。前端、后台作业、证据文件都可以引用同一个意图与计划摘要，避免“界面展示的步骤”和“实际执行的步骤”不一致。

### 闭环测试

- 契约、配置、解析、作业 API 和持久化联合回归：**39/39 通过**。

### 问题与阻塞点

- 当前自然语言属于受控中文命令，不是任意开放式对话；含糊描述会被拒绝并要求明确模组和顺序。

## 5. 阶段3：作业级证据清单

### 修改内容

- 每个异步作业生成 `assembly-evidence-manifest/v1`；
- 对已提交装配体、CAD动作结果、碰撞门禁、事件日志进行路径登记和 SHA-256 校验；
- 每一步记录输入装配体、输出检查点、执行模式、尝试次数、耗时和回滚结果；
- 只有作业成功且所需证据全部存在，才标记 `staticExecutionAccepted=true`。

### 功能意义

“程序返回成功”不再等于“装配完成”。必须同时具备实体文件、保存重开结果和碰撞门禁证据，才能形成可复核结论。

### 闭环测试

- 证据哈希、缺失门禁拒绝、原子写盘及 CAD 作业联合回归：**52/52 通过**。

### 问题与阻塞点

- 对约60 MB装配体执行哈希会增加磁盘读取时间。当前优先保证证据可信；后续可使用“文件版本＋大小＋修改时间＋按需哈希”优化重复读取。

## 7. 当前执行原则

1. 任何已确认的几何、顺序、可达和碰撞约束必须在候选生成/逐步提交阶段执行；
2. AABB严格分离的普通对象对直接通过；允许包围盒重叠或具有门洞/嵌套语义的对象对进入条件 B-rep；
3. B-rep发现新增干涉时，该步不提交，回滚到最后一个已验收检查点；
4. 已确认的碰撞结果通过版本化指纹缓存复用，源文件、位姿或策略变化时缓存失效；
5. 静态装配通过不代表动态运动安全，生产动态放行必须独立判断。
