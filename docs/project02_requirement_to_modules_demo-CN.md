# 项目02“需求 → 模组 → 布局求解”Demo

## 1. 阶段目标

本阶段验证一条最小可用闭环：使用者输入项目02的自然语言工艺需求，系统识别所需能力，推荐对应模组，补齐必要依赖；使用者确认后，结果直接进入现有八模组布局求解器。

本阶段不试图解决任意项目、任意模组组合，也不使用大模型生成不可审计的结论。推荐结果由项目02的显式规则产生，可复现、可解释、可测试。

## 2. 实现原理

处理链路如下：

```text
自然语言需求
    ↓ 关键词、否定词和数量识别
工艺能力集合
    ↓ 依赖闭包
完整能力集合
    ↓ 能力—模组映射
必选/可选模组及推荐理由
    ↓ 人工确认与求解器兼容性门禁
项目02布局求解与展示
```

能力层用于隔离“用户怎样描述需求”和“CAD模组叫什么”之间的差异。例如，用户只提出点胶，系统会补齐产品传输、载具定位和胶水供应依赖，而不是直接把一句话机械映射成一个模组。

## 3. 项目02模组知识库

| 模组 | 功能 |
| --- | --- |
| A100 | XYZ龙门与双阀点胶执行 |
| A180 | 条码扫描与追溯 |
| A200 | CCD视觉定位 |
| A300 | 排胶与废胶收集 |
| A500 | 胶阀/喷嘴校准 |
| A700 | 清洁与称重 |
| A800 | 产品传输与载具定位 |
| T401 | 胶水供应 |

当前规则覆盖点胶、传输、定位、扫码、视觉定位、校准、清洁、称重、排胶和供胶十类能力。依赖规则会自动完成以下补齐：

- 点胶需要传输、载具定位和供胶；
- 扫码需要传输；
- CCD视觉定位需要传输和载具定位；
- 校准、清洁、称重、排胶和供胶均依赖点胶主流程。

## 4. 已实现功能及意义

1. **自然语言需求解析**：识别工艺能力、产品数量和显式否定，降低 Demo 输入门槛。
2. **依赖自动补齐**：防止只选择局部功能而遗漏完整工艺链所需基础模组。
3. **必选/可选分级**：必选模组不可取消；基础点胶场景下，扫码、CCD、校准、清洁/称重和排胶作为可选增强项展示。
4. **推荐理由与能力覆盖**：每个模组显示由哪项显式需求或依赖规则触发，结果可审计。
5. **人工确认门禁**：确认时重新校验必选模组，避免前端选择绕过规则。
6. **求解器兼容性门禁**：当前布局求解器只接受项目02完整八模组基线；不兼容的子集可以推荐和确认，但不会被误送入固定八模组求解器。
7. **推荐结果持久化**：最新推荐与确认结果分别保存为 JSON，支持复核和后续扩展。
8. **展示层衔接**：完整八模组确认后自动调用现有项目02快速布局求解，并继续显示约束指标、方向、边界和人工目测门禁。

## 5. 接口与中间数据

- `POST /api/demo/cases/project02/recommend-modules`：输入需求文本，返回能力、依赖、模组、理由、覆盖情况、假设和缺失信息。
- `POST /api/demo/cases/project02/confirm-modules`：输入推荐编号和用户选择，返回确认结果及是否允许进入当前布局求解器。
- 推荐记录：`demo/requirements/project02_latest_recommendation.json`
- 确认记录：`demo/requirements/project02_confirmed_modules.json`

## 6. 闭环测试结果

测试日期：2026-08-25。

- 项目02需求推荐专项测试：6/6 通过；
- 后端完整单元测试：57/57 通过；
- 后端 Python 编译检查：通过；
- 前端 TypeScript/Vite 生产构建：通过；
- 真实 HTTP 闭环：推荐、确认、布局求解三个接口均返回 200；
- 默认完整需求：10/10 能力覆盖、8 个必选模组、求解器兼容；
- 确认后布局结果：8 个模组，工艺约束 14/14、空间约束 13/13、2.5D交互 36/36；
- 浏览器展示复核：推荐、确认和求解结果均可见，无横向页面溢出。

上述结果只证明“需求推荐—人工确认—离线布局展示”的软件闭环。现有布局结果仍为 `productionReady=false`，不能替代 SolidWorks Replay、条件 B-Rep、运动扫掠和维护空间验收。

## 7. 当前局限

- 仅支持项目02，知识库和依赖规则仍为项目专用；
- 自然语言解析采用确定性词典，不处理复杂长句、同义词歧义和隐含业务规则；
- 当前布局求解器仍固定为完整八模组，尚不能对任意确认子集自动重建约束和求解；
- 推荐只判断功能完整性，不决定设备节拍、冗余、品牌型号和采购选型；
- 推荐结果进入的是快速布局展示，实体无干涉仍需后续 CAD 门禁。

## 8. 下一阶段建议

1. 把能力、依赖和能力—模组映射迁移为版本化 JSON/YAML 配置；
2. 让求解器从确认后的模组集合动态生成变量、约束和展示数据，解除固定八模组限制；
3. 增加澄清问题机制，对节拍、产品数量、是否扫码/称重等缺失条件进行最少轮次追问；
4. 增加需求用例回归集和规则冲突检查；
5. 在项目02稳定后，按同一能力本体接入项目01、03、05、06，并保留项目差异配置。
